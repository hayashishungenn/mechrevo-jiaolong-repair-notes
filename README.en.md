# MECHREVO JIAOLONG (Ryzen 9 9955HX) — Bluetooth Disappearance & Audio Crackling Repair Log

English | [简体中文](README.md)

> Date: 2026-11-23 · Windows 11 24H2/25H2 · Status: Fixed
>
> One laptop with two problematic chips on board (MediaTek MT7922 Wi-Fi/BT combo card +
> Realtek RTL8125 Ethernet). Three seemingly unrelated symptoms — Bluetooth vanishing,
> audio crackling, and the speaker output disappearing — turned out to share one root cause.

## Machine Info

| Item | Model |
|---|---|
| Laptop | MECHREVO JIAOLONG series |
| CPU | AMD Ryzen 9 9955HX (Fire Range, 16 cores) |
| GPU | NVIDIA GeForce RTX 5070 Ti Laptop |
| Wi-Fi/BT card | MediaTek MT7922 (Wi-Fi 6E, AzureWave module, SUBSYS_59111A3B; Wi-Fi on PCIe, Bluetooth on USB) |
| Ethernet | Realtek RTL8125 2.5GbE (PCIe, behind AMD GPP root port 0:1:6) |

## Symptoms

1. **Bluetooth disappears entirely**: tray icon and Settings toggle gone;
   `MediaTek Bluetooth Adapter` shows up as a phantom device in Device Manager
   (`CM_PROB_PHANTOM`, Present=False). A normal restart does not bring it back.
2. **Audio crackling** (predates the Bluetooth issue): built-in speakers suddenly
   produce popping/crackling noise.
3. **Speaker output disappears**: after repeated crackling episodes, all audio output
   devices vanish and the tray speaker icon turns into a red X ("no audio output found").

## Key Diagnostic Evidence

| Evidence | Data | Points to |
|---|---|---|
| WHEA-Logger Event 17 (corrected hardware errors) | 11,133 events in 30 days; 11,116 of them (99.8%) from PCI root port 0:1:6 | The error-storm source |
| Devices behind root port 0:1:6 | RTL8125 Ethernet NIC | Storm generated by the Realtek link |
| MT7922 Bluetooth adapter | `CM_PROB_PHANTOM`, Present=False, while all Bluetooth services (bthserv etc.) run normally | Hardware-level drop-off, not a software issue |
| BTHUSB Event 18 (cannot store link keys) | One event every 5 minutes for hours before the drop-off | Bluetooth firmware hang precursor |
| Time correlation | The Bluetooth card died while the error storm was bursting; the crackling "had been there for a while" matches the 10,008-events-in-one-day storm peak (Nov 20) | All three symptoms share one cause |
| Driver versions | Audio 10.0.1.38 (Apr 2024), Wi-Fi 3.4.0.1115 (Oct 2024), chipset outdated | Stale drivers amplified the problem |

### Root Cause

- **The error storm**: the RTL8125's PCIe link continuously produces corrected AER
  errors, reported by the AMD root port. During bursts, bus transactions stall →
  dropped audio data (crackling) → under sustained storms, downstream devices hang
  (speakers disappear with the red X).
- **The vanishing Bluetooth**: the MT7922's Bluetooth controller firmware hangs and
  drops off the USB bus. The card's Wi-Fi runs on PCIe while Bluetooth runs on USB,
  which is why Wi-Fi keeps working while Bluetooth disappears. A warm reboot cannot
  clear the hung state — **only a full power drain resets it**.
- Both chips are well-known cross-brand, cross-platform problem parts; this laptop
  simply has both of them.

## Fix (in execution order)

1. **Full power-drain cold boot**: shut down → unplug the AC adapter → hold the power
   button for 30 s → wait 1–2 min → power on.
   The only way to recover Bluetooth; a normal restart does not work.
2. **Disable PCIe Link State Power Management**: set PCI Express → Link State Power
   Management to "Off" in the power plan (both AC and battery).
3. **Disable the Realtek RTL8125 Ethernet NIC** (unused on this machine) —
   cuts the error storm off at its source.
4. **Update drivers**:
   - MT7922 WLAN: 3.4.0.1115 → 3.6.0.1434 (Microsoft Update Catalog)
   - AMD chipset: 8.09.28.1124 (AMD official)
   - Audio APO: 1.0.4.55794 (Windows Update)
5. **BIOS** (optional, not done here): shipped as N.1.12MRO13 (Apr 2025); check the
   vendor for a newer release.

## Post-Fix Verification

- After disabling the Ethernet NIC: **zero** new WHEA Event 17 entries
  (previously 1,000+ within half an hour)
- MT7922 WLAN now on driver 3.6.0.1434, Wi-Fi connected normally (2.4 Gbps)
- Bluetooth adapter back online (Status OK), all peripherals pair normally

## Quick Recovery Reference

**If Bluetooth disappears again** (a known MT7922 flaw; the new driver only lowers the odds):

> Shut down → unplug the AC adapter → hold the power button for 30 s → wait 1–2 min → power on

Note: it must be a true "Restart" or a full power drain. With Fast Startup enabled,
"shut down then power on" is NOT a cold boot (the kernel resumes from a hibernation
image, carrying the broken device state back in).

**Re-enabling Ethernet** (if a wired connection is temporarily needed): Device Manager →
Network adapters → right-click "Realtek Gaming 2.5GbE" → Enable device. Disable it again
afterwards.

**How to check for a relapse**: in Event Viewer, filter the System log by provider
`Microsoft-Windows-WHEA-Logger`, Event ID 17. A fast-growing count means the error storm
is back — first check whether ASPM got reset in the power plan or the Ethernet NIC got
re-enabled.

The mitigations known in the Linux community (disable ASPM, full power drain, disable
AER reporting, replace the card) map one-to-one onto the Windows fixes in this log.

## Remaining Items

- AMD audio driver (HD Audio 10.0.1.38, Apr 2024) not updated: its delivery channel is
  inside the full AMD Adrenalin package, which brings GPU software along — deferred
  pending observation
- No newer MECHREVO BIOS confirmed (flashing is risky; only consider if the above fails)
- Long-term option (if the storm relapses and disabling the NIC is not acceptable):
  replace the M.2 Wi-Fi card (e.g., Intel AX210) and rework the Ethernet solution
